White M4 Setup Guide (ROS2 Firmware)

This repository contains the ROS2 firmware for the White M4 robot.
Assumes the robot is fully assembled.

NOTE: This guide replaces the old ROS1/Docker-based workflow.
      No Docker is required. The firmware runs directly on the Jetson.


==============================
1. Setup Jetson
==============================

On Jetson (Jetson Orin / Jetson-ARK / Holybro)

--- 1.1 Prerequisites ---

Install ROS2 Humble:
  https://docs.ros.org/en/humble/Installation.html

Install colcon:
  sudo apt install python3-colcon-common-extensions

Install FastDDS (PX4 DDS bridge — required for px4_msgs):
  Follow PX4 ROS2 user guide:
  https://docs.px4.io/main/en/ros2/user_guide.html


--- 1.2 Clone Repository ---

cd ~
git clone --recursive git@github.com:Taoran2023/m4-firmware-ros2.git whiteM4_ros2/m4-firmware-ros2

cd whiteM4_ros2/m4-firmware-ros2
git submodule update --init --recursive

# Switch submodule to ros2 branch
cd m4_home/m4_ws/src/m4-firmware
git switch ros2
cd ~/whiteM4_ros2/m4-firmware-ros2


--- 1.3 Build Workspace ---

cd m4_home/m4_ws
source /opt/ros/humble/setup.bash
colcon build --cmake-args -DCMAKE_BUILD_TYPE=Release

# Verify build succeeded
ls install/m4_firmware


--- 1.4 Configure USB Rules ---

cd ~/whiteM4_ros2/m4-firmware-ros2/setup_scripts

# Review and adjust 11-local.rules for your Jetson board:
# - U2D2 (FTDI FT232H):   vendor=0403  product=6014  → /dev/U2D2
# - Pixhawk (Cube Orange): vendor=2dae  product=1058  → /dev/pixhawk
vim 11-local.rules

sudo ./set_udev_rules.sh

# Verify devices appear after reconnecting USB:
ls /dev/U2D2 /dev/pixhawk


--- 1.5 Auto-start on Boot (optional) ---

Refer to:  start_up_note.txt



==============================
2. Configure Dynamixel Servos
==============================

Config path:
  m4_home/m4_ws/src/m4-firmware/config/

Key files:
  robot_config.yaml    — joint IDs, calibration ticks, wheel params
  motor_config.yaml    — Dynamixel control table (do NOT modify if using XM540-W270-R)
  rc_channel_config.yaml — RC channel mapping


--- On Laptop (Dynamixel Wizard) ---

1. Disconnect U2D2 from Jetson, connect to laptop.

2. Assign servo IDs:
   Joints (transform): IDs 1–8
     1: FL_Frontal   2: FL_Saggital
     3: FR_Frontal   4: FR_Saggital
     5: BL_Frontal   6: BL_Saggital
     7: BR_Frontal   8: BR_Saggital
   Wheels:             IDs 9–12
     9: FL_Wheel    10: FR_Wheel
    11: BL_Wheel    12: BR_Wheel

3. Calibrate transform joints (IDs 1–8):
   - Move each servo manually
   - Record zero_tick, min_tick, max_tick
   - Update robot_config.yaml
   NOTE: zero_tick and min_tick must be recorded in STAND configuration

4. Set wheel joints (IDs 9–12) to VELOCITY control mode.

5. Reconnect U2D2 to Jetson.


--- RC Channel Configuration ---

Edit: config/rc_channel_config.yaml

Default mapping (update channel_id / PWM values to match your transmitter):

  arm:         Ch6  — disarm / ground_arm / aerial_arm
  drive_mode:  Ch9  — stand / crouch1 / crouch2
  uav_mode:    Ch8  — drive / uav_transform
  auto_mode:   Ch10 — manual / auto  (mid+high both = AUTO)
  x_velocity:  Ch2
  y_velocity:  Ch1



==============================
3. Setup Flight Controller
==============================

M4 uses PX4 as the flight control software.
Communication uses DDS (uXRCE-DDS) — no MAVROS required.

Follow: doc/PX4_Setup_Note/ for details.

Key points:
- Enable uXRCE-DDS agent on Jetson (or use Micro-XRCE-DDS Agent)
- PX4 topics are accessed via px4_msgs package
- RC input arrives at: /fmu/out/input_rc
- Vehicle commands sent to: /fmu/in/vehicle_command



==============================
4. Verify Setup
==============================

--- 4.1 Check USB Devices ---

ls /dev/U2D2       # Dynamixel adapter
ls /dev/pixhawk    # Flight controller

If missing, re-run setup_scripts/set_udev_rules.sh


--- 4.2 Check RC Input ---

cd ~/whiteM4_ros2/m4-firmware-ros2/m4_home/m4_ws
source install/setup.bash

# Check RC topic is publishing (requires uXRCE-DDS agent running)
ros2 topic hz /fmu/out/input_rc
ros2 topic echo /fmu/out/input_rc

- Verify all channels respond to transmitter input
- Adjust rc_channel_config.yaml if needed


--- 4.3 Check Servo Configuration ---

WARNING: Lift the robot off the ground before testing!

cd ~/whiteM4_ros2/m4-firmware-ros2/m4_home/m4_ws
source install/setup.bash
ros2 launch m4_firmware m4_control.launch.py

Expected:
  - Robot performs sit → stand sequence on startup
  - RC arm switch (Ch6 middle) enables ground driving
  - RC joystick (Ch1/Ch2) moves wheels

If robot does not reach STAND:
  - Check servo IDs and calibration in robot_config.yaml
  - Check /dev/U2D2 is present and accessible


--- 4.4 Full Pipeline Test ---

1. Place robot on ground in sit configuration.

2. Start system:
   cd ~/whiteM4_ros2/m4-firmware-ros2
   ./startup.sh

   This creates a tmux session named "control" and launches:
     ros2 launch m4_firmware m4_control.launch.py

3. Attach to session to view logs:
   tmux attach -t control

4. Expected:
   - Robot transitions from sit → stand
   - RC control fully operational
   - Log shows "M4 Controller Node Initialized!"

5. Shutdown:
   cd ~/whiteM4_ros2/m4-firmware-ros2
   ./shutdown.sh



==============================
5. AUTO Mode (optional)
==============================

AUTO mode allows software topics to replace RC joystick input.
Requires a compatible localization source (FastLIO or OptiTrack MoCap).

Configure:  config/robot_config.yaml → auto_mode section

  auto_mode:
      odom_source:          "fastlio"    # or "mocap"
      odom_topic:           "/fastlio/odom"
      odom_timeout_s:       0.5
      odom_lost_descent_mps: 0.3
      uav_arm_wait_s:       5.0

Control topics:
  /auto/mode_cmd   (custom_msgs/M4ModeCmd)  — 0=STAND 1=UAV 2=CROUCH1 4=CROUCH2
  /auto/waypoint   (geometry_msgs/PoseStamped)
  /auto/cmd_vel    (geometry_msgs/Twist)

See: dev_note/auto_mode_DevNote.md for full details.
